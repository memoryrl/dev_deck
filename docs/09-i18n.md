# 09. 다국어 (i18n)

참고: `glow_platform` 프론트 (`i18n.js`, `languageConstants.js`, `languageUtils.js`, `LanguageRouteSync.jsx`, `HeaderLanguageSwitcher.jsx`, `locales/ko.json`·`en.json`).

Glow는 i18next + 쿼리 `?lang=` + 쿠키 `lang` + localStorage다. DevDeck은 **같은 언어 모델·스위처 UX**를 쓰되, App Router RSC에 맞춰 **사전 JSON + 쿠키 SSR**로 구현한다. i18next 런타임은 넣지 않는다.

## 1. 범위

**포함**

- UI 크롬: 헤더·푸터·사이드바·로그인·목록·댓글·랜딩 카피·Steam 탭·공통 버튼/날짜
- 지원 언어: `ko`(기본), `en`
- 언어 선택기: 공개 페이지는 푸터(로고 아래 스택 뱃지 밑). 대시보드는 사이드바 솔루션명 옆, 좁은 화면은 햄버거 메뉴
- 선택 유지: URL `?lang=` → 쿠키 `lang` → localStorage `i18nextLng` → `Accept-Language` → `ko`
- `document.documentElement.lang` / `<html lang>` 동기화

**제외**

- DB 본문(글·댓글·메뉴 라벨·리뷰)의 자동 번역. 작성 언어 그대로 표시
- 경로 프리픽스 `/en/...` (Glow와 같이 쿼리·쿠키만)
- 세 번째 언어, CMS 기반 번역 관리 화면

## 2. 결정

| 항목 | 선택 |
| --- | --- |
| 기본 언어 | `ko` |
| 스위처 | Glow와 동일: 글로브 + Language, 옵션에 국기·한국어/English |
| SSR 소스 | 쿠키 `lang` (미들웨어가 `?lang=`·Accept-Language로 채움) |
| 클라이언트 동기화 | `?lang=` 변경 시 쿠키·localStorage·`html.lang` 갱신 후 `router.refresh()` |
| 보간 | Glow와 동일 `{{count}}` |
| 날짜 | `ko`: `2026-09-16 (수) …`, 상대시각 `오늘` / `en`: `Wed` 약어, `Today` |

## 3. 파일

```text
locales/ko.json
locales/en.json
lib/i18n/config.ts          SUPPORTED, cookie, normalize
lib/i18n/dictionary.ts      getDictionary / getT
lib/i18n/t.ts               키 조회 + {{var}}
lib/i18n/apply-language.ts  쿠키·storage·html.lang (클라이언트)
components/i18n/i18n-provider.tsx
components/i18n/language-switcher.tsx
components/i18n/language-route-sync.tsx
middleware.ts               ?lang= 및 Accept-Language → Set-Cookie
```

## 4. 키 규칙

점 경로. 네임스페이스 예: `language.*`, `common.*`, `nav.*`, `role.*`, `landing.*`, `steam.*`, `list.*`, `comments.*`, `auth.*`, `dashboard.*`, `footer.*`, `theme.*`.

브랜드명(DevDeck, PromptKit, CareerLog, Steam)은 번역하지 않는다.

## 5. UX

공개 헤더 테마 토글 왼쪽(데스크톱), 모바일은 아이콘만. 대시보드 헤더도 동일. 전환 즉시 크롬 문구가 바뀌고 현재 경로·다른 쿼리는 유지한다.

Owner 전용 대시보드 폼·서버 액션 오류 문구는 이번 범위에서 한글로 둔다. 글·댓글·DB 메뉴 라벨은 작성 언어 그대로다.
